## 阶段 1：纯模糊诊断基线（Day 0.5–3）

**目标**：基于主仓库导出的可解释特征，构建一个简单但可运行的模糊诊断系统作为 baseline。

### 1.1 代码结构规划

- [ ] 在 `Paper/Paper_fuzzy_XFD` 下新建：  
  - `code/fuzzy_system/`：  
    - `membership_functions.py`：常见隶属函数（如三角形/梯形/高斯）。  
    - `rule_base.py`：规则库定义。  
    - `inference_engine.py`：模糊推理与解模糊。  
  - `scripts/`：  
    - `run_fuzzy_baseline.py`：读取特征、执行模糊推理、输出诊断结果。

### 1.2 特征导出

- [ ] 从主仓库选择 1 个标准模型（如 TSPN）和 1 个数据集（THU_018 或 CWRU）；  
- [ ] 利用现有特征提取模块，导出样本级可解释特征（RMS、峭度等）到中间文件（如 `results/fuzzy_features.npy`）。  
- [ ] 在 Fuzzy-XFD 脚本中读取该文件，作为模糊系统的输入。

### 1.3 模糊规则系统实现

- [ ] 为选定的特征定义若干模糊集合（如“低/中/高振幅”，“低/中/高冲击性”）；  
- [ ] 手工设计若干基础规则（针对 2–3 类典型故障）；  
- [ ] 在 `run_fuzzy_baseline.py` 中实现完整推理流程：  
  - 特征 → 隶属度 → 规则激活 → 故障评分 → 故障判决。

产出：  
- 纯模糊诊断 baseline，可在小数据上独立运行并输出基本准确率。

## 阶段 2：模糊–深度混合方案（Day 4–8）

**目标**：在 baseline 上增加与深度模型的融合机制，形成 Fuzzy-XFD 的主方法。

### 2.1 融合策略 A（推荐起步）

- [ ] 选择一个主仓库深度模型（如 TSPN 或 NNSPN），保留其分类输出；  
- [ ] 将模糊系统输出的故障评分作为“校正项”或“置信度补充”：  
  - 例如：最终置信度 = α × 网络置信度 + (1-α) × 模糊评分。  
- [ ] 在 `scripts/run_fuzzy_hybrid.py` 中实现该流程，并比较融合前后性能变化。

### 2.2 融合策略 B（后续扩展）

- [ ] 预留将模糊系统嵌入训练过程的接口（可作为可微模块或附加损失），暂可不实现，只在代码/文档中规划。

产出：  
- 至少一版“深度 + 模糊”的混合方法实验结果（性能表 + 少量案例）。

## 阶段 3：规则优化与可解释性评估（Day 9–14）

**目标**：在规则层面进行数据驱动优化，同时评估规则的可解释性和工程可用性。

### 3.1 规则参数优化

- [ ] 为隶属函数参数定义简单的可调结构（如中心、宽度）；  
- [ ] 实现一个轻量级优化过程（如网格搜索、遗传算法或简化梯度方法），针对验证集性能调整规则参数。  
- [ ] 确保在优化后规则仍保持合理语义（避免“乱七八糟”的区间划分）。

### 3.2 规则可解释性与统计

- [ ] 统计：规则数量、平均前提长度、覆盖率等；  
- [ ] 设计简单的一致性/合理性指标（可基于工程先验规则或专家打分）；  
- [ ] 生成 1–2 张表格用于论文。

产出：  
- 优化前后的规则对比结果（性能 + 可解释性指标）；  
- 若干代表性规则变化案例。
