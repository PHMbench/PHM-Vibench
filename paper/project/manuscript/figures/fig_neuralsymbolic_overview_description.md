### 子项目在框架中的定位

#### 1D-2D_fusion_explainable
- **主要位置**: 信号处理层 + 特征提取层
- **核心功能**: 多模态信号融合、跨模态特征对齐
- **数据流**: 1D信号 + 2D谱图 → 融合特征 → 对齐约束

#### MOE_explainable
- **主要位置**: 全四层覆盖
- **核心功能**: 专家路由、物理解释、路径签名
- **数据流**: 信号 → 专家特征 → 路由逻辑 → 专家解释

#### Paper_fuzzy_XFD
- **主要位置**: 符号推理层 + 特征提取层
- **核心功能**: 模糊规则推理、可解释特征
- **数据流**: 信号 → 统计特征 → 模糊规则 → 规则解释

#### LLM_Explainable_FD_Toolkit
- **主要位置**: 语言解释层 + 符号推理层
- **核心功能**: 自然语言解释、知识图谱推理
- **数据流**: 符号表示 → 知识推理 → 语言解释

#### TII_operator_attention
- **主要位置**: 信号处理层 + 特征提取层
- **核心功能**: 算子注意力、物理约束
- **数据流**: 信号 → 注意力权重 → 算子选择

#### Explainable_FD_Toolkit
- **主要位置**: 全四层接口
- **核心功能**: 统一评估协议、可视化工具
- **数据流**: 提供跨层的标准化接口和评估

#### Neuralsymbolic_theory
- **主要位置**: 跨层理论指导
- **核心功能**: 统一理论框架、形式化验证
- **数据流**: 为所有层提供理论约束和指导

### 关键设计原则

1. **分层透明性**: 每层都有明确的可解释性机制
2. **跨层一致性**: 上层解释与下层决策保持一致
3. **理论统一性**: 所有子项目遵循统一的神经-符号理论
4. **模块化设计**: 各子项目可独立工作，也可协同使用

### 约束机制

- **自底向上**: 信号→特征→符号→语言的信息传递
- **自顶向下**: 语言→符号→特征→信号的约束传递
- **横向对齐**: 同层内部的多模态信息对齐
- **反馈优化**: 解释质量反馈优化模型决策

### 实际应用流程

1. **信号输入**: 原始振动信号和时频谱图
2. **信号处理**: 各子项目的专门化信号处理
3. **特征提取**: 可解释的特征表示和注意力机制
4. **符号推理**: 规则推理和专家决策
5. **语言解释**: 自然语言解释生成和交互

这个统一框架为可解释故障诊断提供了完整的理论基础和实现指导。
