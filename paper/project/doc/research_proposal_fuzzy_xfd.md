# Fuzzy-XFD Research Proposal：模糊逻辑与深度学习结合的可解释故障诊断

> 面向后续 Agent：本文件将 Fuzzy-XFD 的研究构想拆解为具体实现步骤，使你可以在现有仓库基础上构建“模糊规则 + 可解释特征 + 深度模型”的完整方案。

---

## 一、要解决的问题（Problem）

1. **深度模型缺乏“规则级”解释**
   - 即便有可解释特征或热力图，工程师仍难以将模型决策对应到熟悉的「如果…那么…」诊断规则。  
   - 现有解释大多是“连续值”的归因，而传统工程实践更多依赖模糊规则和经验知识。

2. **传统模糊诊断系统的表达能力与自适应性不足**
   - 完全基于人工规则的模糊系统很难覆盖复杂工况和多样化设备。  
   - 缺乏利用数据驱动方式自动优化或生成模糊规则的体系。

3. **缺乏统一框架将模糊逻辑与深度模型结合**
   - 需要回答：如何在统一框架中利用深度模型提取“可解释特征”，再通过模糊规则给出透明决策，同时保持较高性能。

---

## 二、研究内容（Research Content）

1. **基于可解释特征的模糊规则库构建**
   - 使用主仓库的可解释特征（均值、方差、RMS、峭度、谱特征等）作为模糊系统的输入。  
   - 设计具有物理含义的模糊隶属函数（如“振幅高/中/低”“冲击显著”等）。  
   - 构建覆盖主要故障模式的模糊规则集。

2. **模糊推理与深度模型的融合机制**
   - 方案 A：深度模型先做粗分类，模糊系统进一步解释并细化决策置信度；  
   - 方案 B：模糊系统提供规则先验或规则输出，作为深度模型的附加输入；  
   - 方案 C：使用可微模糊层，直接嵌入神经网络中进行联合训练。

3. **规则可解释性与性能的联合评估**
   - 设计指标衡量规则的数量、复杂度、覆盖率以及与工程先验的一致性。  
   - 比较 Fuzzy-XFD、纯深度模型、纯模糊系统在性能和可解释性上的差异。

4. **规则自动化/半自动化优化研究**
   - 探索利用数据对隶属函数参数和规则权重进行优化。  
   - 保持规则在语义上的可理解性（避免变成完全黑盒参数）。

## 三、技术路线（Technical Route）

### 3.1 代码结构规划

建议在 `Paper/Paper_fuzzy_XFD` 下新增：

- `code/`（可新建）：  
  - `fuzzy_system/`：模糊隶属函数、规则库与推理引擎实现。  
  - `integrations/`：与主仓库模型的融合接口。  
  - `utils/`：规则可视化、规则统计等工具。

- `scripts/`：  
  - `run_fuzzy_baseline.py`：仅模糊系统的基线实验。  
  - `run_fuzzy_hybrid.py`：模糊 + 深度模型混合方案实验。

### 3.2 与主仓库的集成方式

1. **特征提取**
   - 使用主仓库数据加载 + 特征提取模块获得每个样本的可解释特征向量。  
   - 将这些特征保存为中间文件（如 `results/fuzzy_features.npy` 或 HDF5）供模糊系统使用。

2. **模糊隶属函数设计**
   - 对各特征定义 2–5 个模糊集合（如低/中/高、轻微/严重等）。  
   - 隶属函数形式可采用三角形、梯形或高斯函数。  
   - 相关参数初始值由工程经验给定，后续可微调。

3. **规则库构建**
   - 按目标设备与故障类型（如正常、轻微不平衡、严重不平衡、内圈故障、外圈故障等）设计规则：  
     - 例如：  
       - IF `RMS` 高 AND `Kurtosis` 高 AND 高频能量高 → 故障 = 冲击类故障（如滚动轴承内圈故障）  
       - IF `RMS` 中 AND `Kurtosis` 低 AND 基频能量高 → 故障 = 对中/不平衡类

4. **融合策略实现**

- 方案 A（推荐起步）：  
  - 深度模型输出类别概率；  
  - 模糊系统输出规则支持度；  
  - 将两者进行融合（如加权平均或贝叶斯融合），同时提供规则解释。

- 方案 B（进阶）：  
  - 将模糊系统作为可微层嵌入模型训练中，对隶属函数参数进行微调。  
  - 注意保持参数在合理范围内，避免失去语义可解释性。

### 3.3 评估协议

- 性能：  
  - 分类准确率、F1、AUC 等标准指标。  
  - 在不同噪声水平和工况下的性能。

- 可解释性：  
  - 规则数量与平均长度；  
  - 覆盖率：规则覆盖了多少百分比的样本；  
  - 一致性：规则与工程师事先给出的诊断要点的匹配程度（可通过简单评分或匹配度量）。  
  - 易理解性：由专家或模拟评分评估规则是否易读、易用。

**支撑创新点**: C2 - 展示模糊推理机制
**位置**: 论文 Results Section - Figure 3

**示例推理链**:
```
输入样本特征:
├── RMS = 2.34 g
├── 峭度 = 4.56
├── 高频能量 = 1.78 g²
└── 包络谱能量 = 0.92 g²

模糊化处理:
├── μ_RMS(中) = 0.67, μ_RMS(高) = 0.33
├── μ_峭度(中) = 0.44, μ_峭度(高) = 0.56
├── μ_高频能量(中) = 0.32, μ_高频能量(高) = 0.68
└── μ_包络谱能量(中) = 0.71, μ_包络谱能量(高) = 0.29

规则激活强度:
├── R3: μ_RMS(高)×μ_峭度(高)×μ_高频能量(高) = 0.33×0.56×0.68 = 0.126
├── R4: μ_RMS(高)×μ_包络谱能量(中)×μ_边带能量(高) = 0.33×0.71×0.42 = 0.099
└── R6: μ_RMS(高)×μ_频谱复杂度(中) = 0.33×0.38 = 0.125

输出解模糊:
├── 内圈故障: Σ(R3激活×权重) / Σ(所有激活) = 0.126×0.92 / 0.350 = 0.33
├── 外圈故障: Σ(R4激活×权重) / Σ(所有激活) = 0.099×0.89 / 0.350 = 0.25
└── 保持架故障: Σ(R6激活×权重) / Σ(所有激活) = 0.125×0.78 / 0.350 = 0.28

最终决策: 内圈故障 (置信度0.33)
```

## 六、讨论（Discussion）

1. **规则数量与可解释性的权衡**
   - 规则过少可能无法覆盖复杂场景，过多则影响理解和维护。  
   - 如何通过剪枝或聚类保持一个“精简而覆盖全面”的规则集。

2. **模糊系统与深度模型的分工边界**
   - 深度模型更擅长从原始信号中提取复杂特征；模糊系统更适合在高层特征上给出决策逻辑。  
   - 讨论不同分工模式对性能和可解释性的影响。

3. **跨设备与跨工况的规则迁移**
   - 某些规则是否可以在不同设备/数据集之间复用或微调？  
   - 规则迁移的策略与可能遇到的问题。

4. **与 Neuralsymbolic 理论及 LLM 工具包的关系**
   - Fuzzy-XFD 可视为神经-符号混合系统的一个具体实例。  
   - 模糊规则可以与 LLM 结合，将规则自动转化为自然语言解释或用于对话系统。
