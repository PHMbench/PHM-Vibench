# LLM Explainable Interface 基线引用模板

## 统一基线结果参考

> 统一基线结果见 `Paper/doc/11_29/codex/unified_baseline_results_codex_11_29.md`。
> 本项目构建LLM驱动的故障诊断解释界面，主要评估自然语言解释的质量和用户体验，而非追求性能提升。

## 实验设计建议

### 评估维度

| 维度 | 统一基线 | LLM增强版 | 评估方法 |
|------|----------|-----------|----------|
| 性能 | [引用] | 持平或略降 | 标准测试集 |
| 可理解性 | 技术报告 | 自然语言 | 用户研究 |
| 解释质量 | 分数/热图 | 对话式解释 | 专家评分 |
| 交互性 | 静态输出 | 动态问答 | 交互测试 |

### 核心实验设计

#### 1. 解释质量对比


#### 2. 用户体验评估

**评估指标**:
- **任务完成度**: 完成诊断任务的准确性
- **时间效率**: 获得理解所需时间
- **满意度**: 主观满意度评分
- **信任度**: 对解释结果的信任程度

**用户群体**:
- 领域专家（维修工程师）
- 技术管理者
- 非技术用户（设备操作员）

### LLM接口设计

#### 对话流程模板
```
用户: "设备出现异常振动，请诊断可能原因"

LLM: "根据分析，检测到以下异常：
1. 主要频率分量：157.3 Hz（内圈故障特征频率）
2. 振动幅值：8.2 mm/s（超出正常范围）
3. 温度变化：+12°C（伴随发热）

诊断结论：疑似轴承内圈早期故障，建议安排检修。

需要更详细的分析吗？"

用户: "为什么判定是内圈故障？"

LLM: "依据如下：
• 频谱分析显示157.3 Hz峰值，与理论计算的内圈故障频率156.8 Hz高度吻合
• 该频率的二次谐波（314.6 Hz）同时出现，进一步确认内圈故障特征
• 振动时域波形呈现出明显的周期性冲击，符合内圈损伤的典型表现..."
```

## 创新点强调

1. **自然语言解释**: 将技术分析转换为易懂的自然语言
2. **交互式诊断**: 支持追问和渐进式深入
3. **个性化适配**: 根据用户背景调整解释详细度
4. **知识融合**: 结合领域知识库提供背景信息
