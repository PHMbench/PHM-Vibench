# PHMFactory v0.3.0 Reader Preservation Contract

Status: accepted for staged implementation  
Applies to: all v0.3.0 repository-cleanup, packaging, Pipeline-rename, UI, data-provider, and release PRs

## 1. Purpose

The v0.3.0 repository cleanup must not discard or silently change the existing
dataset support accumulated under `src/data_factory/reader/`.

A file being old, unusually named, sparsely documented, or similar to another
reader is not sufficient evidence for deletion, merging, or behavioral change.

## 3. Frozen reader behavior

For each reader, the following behavior is frozen during v0.3.0 cleanup work:

- callable name and signature;
- accepted source file type and source keys;
- channel selection and channel order;
- truncation, alignment, stacking, reshape, and transpose behavior;
- returned array rank and axis meaning;
- dtype and byte-order handling;
- numerical transforms and normalization;
- successful-path and error behavior relied upon by current callers.

A cleanup PR must not change these properties merely to make implementations
look uniform.

## 4. Prohibited operations

Without a separately approved reader bug-fix task, do not:

- move or rename `src/data_factory/reader/`;
- rename `reader` to `readers`;
- rename dataset-specific modules;
- convert function-based readers into classes;
- force all readers into one signature;
- merge readers because their names or datasets appear related;
- change MAT, CSV, TXT, HDF5, or spreadsheet field selection;
- change channel order or returned shape;
- add hidden fallback data;
- apply repository-wide Black, isort, Ruff fixes, or mechanical rewrites to the
  protected path;
- remove `THU.py`, `THU24.py`, or another reader solely because it is empty,
  unusual, or currently unverified.

## 5. Allowed non-runtime cleanup

The following changes may be proposed in a dedicated, reviewable diff:

- remove tracked `__pycache__/` and `*.pyc` artifacts;
- classify `reader/output/` and remove confirmed generated output;
- move confirmed golden test evidence into `test/fixtures/` before deleting the
  generated directory;
- remove a personal absolute path from an isolated `if __name__ == "__main__"`
  development block;
- replace such a path with a repository-relative documented example;
- correct documentation that does not match the implementation;
- add focused tests, inventories, hashes, and compatibility warnings outside the
  numerical read path;
- migrate Agent-specific documentation to the personal fork after accurate,
  implementation-backed knowledge is copied into neutral documentation.

These allowances do not authorize changing the runtime callable.

## 6. Generated and documentation paths

### `reader/__pycache__/`

Treat as generated bytecode. Delete from version control and keep ignored.

### `reader/output/`

Classify every tracked item before deletion:

| Classification | Action |
| --- | --- |
| Reproducible generated output | delete and ignore |
| Golden reader fixture required by a test | move to `test/fixtures/readers/` and document provenance |
| Paper/result evidence | migrate to the owning paper repository, verify hash, then delete upstream |
| Unknown | retain pending review |

### `reader/CLAUDE.md`

The filename and Agent-specific workflow do not belong in the neutral upstream
framework. Before removal:

1. preserve the original in the personal fork;
2. compare each technical statement with current code;
3. move only accurate, generally useful content into `reader/README.md` or a
   neutral maintained document;
4. do not copy claims that describe an architecture the code does not implement.

## 7. Reader inventory and support status

The inventory PR must record at least:

```text
module
metadata Name value
status
entrypoint
signature
expected output rank
current import/config consumers
fixture coverage
file SHA256
runtime callable AST or equivalent fingerprint
known limitations
```

Allowed status values are:

```text
maintained
compatibility
experimental
unverified
placeholder
```

Definitions:

- **maintained**: current supported surface with tests and documented consumers;
- **compatibility**: retained for existing consumers but not promoted for new use;
- **experimental**: active implementation outside the release-supported surface;
- **unverified**: implementation exists but current behavior/support evidence is
  insufficient;
- **placeholder**: intentionally or historically empty/incomplete; retained until
  provenance and consumers are resolved.

File presence alone must not be used to claim maintained support.

## 8. Fingerprint gate

Before the first cleanup PR that can touch protected paths, generate a baseline
manifest containing file hashes and callable fingerprints.

For a reader file modified only to remove non-runtime personal content, the
runtime callable fingerprint must be unchanged before and after the edit.

Any unapproved difference is a release blocker. A legitimate behavior fix must
be moved into a separate bug-fix PR with:

- the failing contract exposed by a test;
- before/after behavior evidence;
- compatibility impact;
- explicit approval;
- rollback instructions.

## 9. Pipeline rename interaction

The direct Pipeline rename PR may rename `src/Pipeline_*.py` and update imports,
registry values, configs, and documentation. It must preserve the Pipeline
callable body and must not include reader behavior changes.

Reader changes discovered during that PR are follow-up issues, not opportunistic
edits.

## 10. CWRU quickstart interaction

The maintained CWRU quickstart may consume a prebuilt `RM_001_CWRU.h5` bundle.
That validates provider, metadata, HDF5, Data Factory, DataLoader, model, task,
and trainer integration, but it does not revalidate raw MAT conversion.

v0.3.0 does not require a new raw MAT fixture. Release notes and support claims
must state that limitation accurately.

## 11. Review and rollback

Any PR touching protected paths must list those paths explicitly and show the
fingerprint result. If a reader diff is outside the approved non-runtime scope,
the PR must be split or rejected.

Rollback is file- or PR-level restoration from the recorded v0.3.0 baseline. Do
not force-push `main`, rewrite a published tag, or mask a fingerprint difference
by regenerating the baseline after the change.
